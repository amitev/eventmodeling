- Martin: I ask AI to walk me through the new feature ("Walkthrough" is a skill as well) - It suggests what needs to change, which slices need adjusting and which new slices are required. That gives me a pretty good picture of what needs to happen. Then I review the walkthrough using existing skills like “wdyt?” (“what do you think”) and "scenario coverage". Finding the gaps while it´s cheap. In addition, Scenario coverage tells me how wide the safety net is. The scenarios in the event model are a reflection of the logic in the code.
- Martin: Then I build the feature with one of the prepared build kits or with the “classic” build kit, which works in your codebase and follows the patterns it found earlier.
- Martin: Last but not least, I check for drift after implementation, I typically run the model drift skill to make sure the code and the model still match. I also do this continuasly. AI detects any drift from the model and adjusts the model from code.
You can do this at any point, even much later. In an EVL (L=legacy) codebase, it might be crucial after some PR reviews. It’s the same process every time.

- Build slices - skills for building the slice types. Agent should also read the chapter and lane docs.
- Agent Tasks - Places an Agent-Task, that is picked up by an agent and worked on. Each Tasks holds it´s context. So the agent know what you were looking at on the screen at the time you placed the task.
- Agent Cockpit - The Agent Cockpit gives full control and visibility for Agent Activities across all Boards. In this example we are putting two tasks into status 'planned' - which allows an agent to pick them up.
- Agent Chat - The Agent Chat allows you to interact with an agent directly. The Chat is Context-Aware - means every chat message carries a snapshot of your screen. The Agent knows exactly what you were looking at. And you can render any kind of visualization or report - in this case I needed a Bar-Chart of the number of slices.
